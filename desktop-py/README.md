# ImpactMap Desktop

[Установка и запуск на Windows и Fedora KDE](../README.md).

- **GitHub**. Введите `владелец/репозиторий` или вставьте HTTPS-ссылку на публичный репозиторий. Нажмите «Проверить изменения». ImpactMap сравнит последний коммит ветки по умолчанию с его первым родителем. Для первого коммита исходный снимок пуст.
- **Локальная папка**. Выберите Git-репозиторий с хотя бы одним коммитом. Проверка сравнит `HEAD` с рабочей папкой, включая новые файлы вне правил игнорирования. Снимки создаются во временном каталоге.
- **Попробовать на примере**. ImpactMap подготовит временный Git-проект из трёх файлов Python, изменит `helpers.py` и запустит обычную проверку. Если бинарник отсутствует, приложение явно помечает сохранённый результат примера.

**Обзор** объясняет находки и ограничения. На **Карте** стрелка `A → B` означает, что файл A использует B. Выберите файл на схеме или в списке над ней, чтобы выделить его цепочку. Флажок «Только выбранная цепочка» скрывает остальные связи. Перетаскивайте схему мышью и меняйте масштаб колёсиком или кнопками. Во вкладке **Файлы и подробности** доступны статусы, цепочки и полные сообщения анализатора.

Сеть нужна для загрузки с GitHub. Анализ выполняется локально. Чтобы выбрать другой бинарник, передайте `--analyzer ПУТЬ` или задайте `IMPACTMAP_ANALYZER`. Старые бинарники v1 показывают связи и предупреждения. Сравнение объявлений и исторических импортов требует нового бинарника. [Протокол анализатора](../analyzer-rs/README.md).

Тесты настольного клиента можно запустить из корня репозитория.

```sh
QT_QPA_PLATFORM=offscreen python -m unittest discover -s desktop-py
```

Для проверок с настоящим бинарником задайте `IMPACTMAP_TEST_ANALYZER`. Сценарии GitHub дополнительно включаются через `IMPACTMAP_TEST_GITHUB=1`.

## Новое в 0.0.3

После загрузки проекта выберите исходник в списке **«До изменения файла»**.
Прогноз доступен даже при чистом рабочем дереве: выбранный файл помечается как
«Планируется», показываются обратные зависимости и кратчайшие цепочки. Прогноз
использует текущий загруженный снимок и не меняет файлы. Обновление снимка —
кнопкой «Проверить изменения». Пункт «Показать проверенные изменения» возвращает diff.

Нужен анализатор с полями `files` и `current_edges` (0.0.3). Для старого бинарника
или сохранённого примера прогноз отключён с пояснением, обычный просмотр работает.
`files` позволяет выбирать также изолированные исходники. Предупреждения о
неразобранных файлах остаются видимыми; пустой прогноз не означает безопасность правки.

Кнопка **«Сохранить HTML…»** экспортирует текущий прогноз или сравнение. Отчёт
содержит цепочки, находки и предупреждения, без сетевых ресурсов и скриптов.
Его можно передавать другим людям; в нём присутствуют имена файлов и диагностика.

Для отчёта без PySide6 используйте `python3 desktop-py/report_cli.py --help`.
Например: `python3 desktop-py/report_cli.py --demo --file helpers.py`.
