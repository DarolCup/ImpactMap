# ImpactMap 0.0.3: разбор и передача работы

## Краткая оценка исходного состояния

База main `f5fac82` уже частично выполняла идею: существовали реальный Rust-анализатор,
обратный обход зависимостей, кратчайшие цепочки, сравнение API/удалений, desktop-карта,
загрузка публичного GitHub-репозитория. Проект нельзя считать пустой демонстрацией.

Что мешало выполнять исходную задачу:

1. Основной интерфейс проверял уже сделанный Git diff. Выбрать неизменённый файл
   и оценить влияние до редактирования было нельзя.
2. Файлы без рёбер отсутствовали в карте, отдельного каталога исходников не было.
3. Граф сравнения содержал исторические рёбра: его нельзя безоговорочно использовать
   для прогноза текущего снимка.
4. Абсолютные импорты из `desktop-py` самого ImpactMap не разрешались: известны были
   только корень и `src/`. Нестандартные корни не настраивались.
5. Для передачи результата требовалась установка приложения; корневой README
   описывал преимущественно локальный режим и отставал от возможностей GitHub.

## Что сделано

- `codex/rust-0.0.3`: поля v1 `analyzer_version`, `files`, `current_edges`;
  `.impactmap.json` с дополнительными `python_source_roots`; тесты и контракт.
- `codex/python-0.0.3`: создана **поверх Rust-ветки**, содержит обе части для запуска.
  Выбор файла до изменения, отдельный прогноз, возврат к diff, изолированные файлы,
  HTML-экспорт и `report_cli.py` без PySide6, документация и интеграционные проверки.
- Версии приложения и Rust crate согласованы на 0.0.3 (у crate раньше отдельно
  стояло 0.1.0). Версия JSON-протокола остаётся 1.

Для интеграции можно сначала слить Rust-ветку, затем Python-ветку, либо сразу
Python-ветку целиком. Старые `agent/rust-analyzer`, `agent/python-desktop` и main
не переписывались. Это один продукт с двумя компонентами, не два независимых приложения.

## Проверка и демонстрация

```sh
cargo build --release --locked --manifest-path analyzer-rs/Cargo.toml
cargo test --locked --offline --manifest-path analyzer-rs/Cargo.toml
QT_QPA_PLATFORM=offscreen IMPACTMAP_TEST_ANALYZER="$PWD/analyzer-rs/target/release/impactmap-analyzer" IMPACTMAP_TEST_GITHUB=1 python3 -m unittest discover -s desktop-py
python3 desktop-py/report_cli.py --demo --file helpers.py --output /tmp/impactmap-demo.html
python3 desktop-py/report_cli.py --local . --file desktop-py/analysis.py --output /tmp/impactmap-self.html
```

На Windows используйте переменные окружения PowerShell и путь к `.exe`.
Без `IMPACTMAP_TEST_GITHUB=1` сетевой тест пропускается. Без настоящего бинарника
часть интеграционных тестов пропускается; это не полноценная проверка релиза.

Покрыты чистое дерево без diff, прямое/транзитивное влияние, циклы, равные маршруты,
изолированный файл, исключение исторических рёбер, неизменность исходных файлов,
возврат из прогноза к сравнению, экспорт, экранирование HTML, пользовательские
корни импортов и загрузка двух публичных репозиториев. GUI проверен offscreen на Linux.
Windows в этой сессии не проверялся. `cargo fmt` и `cargo clippy` недоступны в
окружении (компоненты не установлены); перед релизом запустить их в настроенном CI.

## Где продолжать

1. Добавить выбор ветки/PR и понятный прогресс загрузки GitHub. Для приватных
   репозиториев пока используется локальный clone; OAuth не реализован.
2. Подготовить готовые сборки Windows/Linux и CI: сейчас Rust нужно собирать.
3. Улучшить покрытие Rust-обращений без `use` и Python re-export; не объявлять
   отсутствие найденных связей гарантией отсутствия риска.
4. Большие репозитории: ограничить/виртуализировать полную карту, добавить поиск
   в выборе файла. Сейчас список и карта рассчитаны на небольшие демонстрации.
5. Прогноз в Python делает обратный BFS по `current_edges`, отдельно от Rust BFS.
   Тест сверяет результат с настоящим бинарником. При изменении направления рёбер
   или выбора кратчайших цепочек поддерживать оба компонента согласованными.

Не смешивать прогноз с доказательством ошибки: выбранный файл не изменялся,
в прогнозе нет находок об API/удалении. Снимок не обновляется автоматически.
